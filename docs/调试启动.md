# 调试启动

本文用于调试 `openclaw_lab_adapter` 当前最核心的两条链路：

```text
链路 1：自然语言/地点名 -> scout_navigation_manager -> YAML 坐标映射 -> move_base -> 1201 地图导航
链路 2：自然语言 -> scout_main_agent(Kimi) -> skill 选择 -> scout_navigation_manager / scout_move_control
```

默认基准地图：

```text
sailors_onboard-main/sailors_onboard-main/ros1_ws/vendor/control/scout_control/scout_launch/maps/1201.yaml
```

项目关系：

- `openclaw_lab_adapter`：当前适配开发与联调主项目
- `sailors_onboard-main`：小车端实际运行代码
- `openclaw`：只作 skill 组织方式参考

## 1. 调试前提

开始前建议确认：

- 无人车底盘已上电
- 激光、IMU、里程计等导航相关传感器已启动
- ROS1 环境可以正常 `source`
- `1201` 地图是当前实际运行的地图
- 机器人在 RViz 中已有稳定定位
- 项目根目录下 `.env` 已配置模型密钥

如果底层 `move_base` / `amcl` / `map_server` 没有正常运行，导航 skill 只能“接口起来”，不能真正移动。

## 2. 启动小车实际环境

实际小车的启动流程已经封装在下面目录中的 4 个脚本里：

```bash
/ssd1/workspace/quick_start
```

执行前先加载 ROS1 Noetic 环境：

```bash
source /opt/ros/noetic/setup.bash
```

```text
1. start.bash
2. nav.bash
3. sensing.bash
4. 连接小车相关脚本（当前联调暂时不用）
```

建议按下面顺序执行。

### 2.1 加载 ROS1 环境

```bash
source /opt/ros/noetic/setup.bash
cd /ssd1/workspace/quick_start
```

预期：

- 没有报错
- 当前终端可以正常执行 `roslaunch`、`rostopic`、`rosnode`

### 2.2 启动基础服务

```bash
bash start.bash
```

预期：

- 服务正常启动
- 底盘驱动、基础传感器、底层 ROS 节点开始输出日志
- 不应持续出现 `cannot open serial`、`device not found`、`can0` 异常之类硬错误

可额外检查：

```bash
rostopic list | grep -E "/scan|/imu|/odom|/cmd_vel"
```

预期输出示例：

```text
/scan
/imu
/odom
/cmd_vel
```

### 2.3 启动导航

```bash
bash nav.bash
```

预期：

- 地图、定位、导航相关节点启动
- 后续可以接收导航目标
- `map_server`、`amcl`、`move_base`、`rviz` 正常启动

可额外检查：

```bash
rosnode list | grep -E "map_server|amcl|move_base"
```

预期输出示例：

```text
/amcl
/map_server
/move_base
```

### 2.4 启动感知节点

```bash
bash sensing.bash
```

预期：

- 感知相关节点启动
- 终端开始输出传感器或感知模块日志

### 2.5 第 4 个脚本

第 4 个脚本是连接小车相关脚本。

当前 `openclaw_lab_adapter` 联调时，前 3 个脚本通常已经够用，第 4 个脚本暂时可以不启动。

说明：

- 旧文档中提到的 `roslaunch scout_launch startup.launch`、`roslaunch scout_launch nav.launch`，本质上已经被上面的脚本封装
- 实际联调时优先使用 `/ssd1/workspace/quick_start` 下的脚本，不再建议手动分散执行底层 `roslaunch`

## 3. 启动项目侧服务

另开一个终端：

```bash
cd /path/to/openclaw_lab_adapter
source /opt/ros/noetic/setup.bash
```

### 3.1 可选：编译自定义服务

将 `ros1_bridge/scout_openclaw_msgs` 放入你的 catkin 工作空间 `src/` 下：

```bash
catkin_make
source devel/setup.bash
```

如果暂时不编译 `SetString.srv`，导航适配层仍可通过 `std_msgs/String` 话题后备运行。

### 3.2 启动桥接服务

```bash
python3 skills/scout_move_control/scripts/move_control_server.py
```

预期：

- 终端输出 `Scout move control server started`

```bash
python3 skills/scout_navigation_manager/scripts/navigation_manager_server.py \
  --waypoints skills/scout_navigation_manager/config/navigation_position.yaml
```

预期输出示例：

```text
Waiting for /move_base action server...
Scout navigation manager started with 5 waypoint(s), map_id=1201, frame_id=map
```

如果一直停在 `Waiting for /move_base action server...`，说明 `move_base` 没起来，或当前终端没有正确 `source` ROS1 环境。

## 4. 启动主智能体

`scout_main_agent.py` 是 `openclaw_lab_adapter` 的项目级主进程入口，不属于 `skills/`。

它的职责是：

- 接收自然语言输入
- 调用 Kimi 模型
- 选择本地 skill
- 将请求转发给 `scout_navigation_manager` 或 `scout_move_control`

### 4.1 查看当前可调度 skills

```bash
python3 agent/scout_main_agent.py --list-skills
```

预期输出示例：

```text
scout_navigation_manager: 将用户的地点类自然语言映射到 1201 地图中的命名导航点，并调用导航客户端发送目标。
scout_move_control: 将简短运动意图转换为底盘动作命令，并调用移动控制客户端下发字符串命令。
```

### 4.2 用 dry-run 方式启动一次主智能体调用

```bash
python3 agent/scout_main_agent.py --text "带我去前台" --dry-run
```

预期：

- Kimi 返回一个自然语言解释
- 主智能体选择 `scout_navigation_manager`
- 不真正执行 ROS 动作，只输出计划结果

预期输出示例：

```json
{
  "reply": "正在为您导航到前台（接待区）...请稍候。",
  "actions": [
    {
      "skill": "scout_navigation_manager",
      "status": "dry_run",
      "arguments": {
        "target": "接待区"
      }
    }
  ]
}
```

### 4.3 执行真实主智能体调用

```bash
python3 agent/scout_main_agent.py --text "带我去前台"
```

预期：

- 主智能体选择 `scout_navigation_manager`
- 本地脚本实际调用 `navigate.py --go 接待区`
- 如果 ROS 环境和导航服务正常，车开始导航

建议：

- 第一次联调优先使用 `--dry-run`
- 确认 skill 选择正确后，再执行真实调用

## 6. 验证导航 skill

### 6.1 查询地点列表

```bash
rosservice call /scout_navigation_manager/list_positions
```

预期输出示例：

```text
success: True
message: "原点,实验台,接待区,物料区,巡检点A"
```

### 6.2 直接发送地点名

```bash
python3 skills/scout_navigation_manager/scripts/navigate.py --go "带我去前台"
```

预期输出示例：

```text
坐标: [接待区] x=1.200 y=-0.800 yaw=0.0
success=True resolved=接待区 message=true
```

服务端预期日志：

```text
Resolved navigation request '带我去前台' -> '接待区' (x=1.200, y=-0.800, yaw=0.0)
```

### 6.3 直接发送底盘动作

```bash
python3 skills/scout_move_control/scripts/move_control_client.py --cmd "forward 1, stop 0.5, left 1"
```

预期输出示例：

```text
sent: forward 1, stop 0.5, left 1
```

### 6.4 检查导航状态

```bash
rosservice call /scout_navigation_manager/navigation_status
```

预期可能经历两个阶段：

```text
success: True
message: "moving to 接待区"
```

到达后：

```text
success: True
message: "finish"
```

### 6.5 输入不存在的地点

```bash
python3 skills/scout_navigation_manager/scripts/navigate.py --go "去火星基地"
```

预期输出示例：

```text
unknown waypoint: 去火星基地
available: 原点,实验台,接待区,物料区,巡检点A
```

### 6.6 如何给 1201 地图添加你自己的点位

1. 启动 `roslaunch scout_launch nav.launch`
2. 在 RViz 中使用 `2D Nav Goal` 标记目标点
3. 记录该点在 `map` 坐标系下的 `x / y / yaw`
4. 将点位写入 `skills/scout_navigation_manager/config/navigation_position.yaml`

配置示例：

```yaml
  样品区:
    x: 1.85
    y: -2.10
    yaw: 90.0
    description: "1201 地图中的样品区"
    aliases:
      - 样品台
      - 去样品区
      - 带我去样品台
```

## 8. 推荐最小闭环

如果只想最快确认“当前 demo 链路已通”，建议最少做下面这组：

1. `roslaunch scout_launch startup.launch`
2. `roslaunch scout_launch nav.launch`
3. 启动 `navigation_manager_server.py`
4. `python3 skills/scout_navigation_manager/scripts/navigate.py --go "带我去前台"`
5. `python3 agent/scout_main_agent.py --text "带我去前台" --dry-run`

预期：

- 第 4 步能把“带我去前台”解析成 `接待区`
- 第 5 步能让 Kimi 选择 `scout_navigation_manager`

只要这两步都通，就说明：

- 导航 skill 本身是通的
- 大模型到本地 skill 的调度链路也是通的

## 9. 常见问题

### 9.1 `ImportError: No module named rospy`

原因：

- 当前终端没有 `source ~/catkin_ws/devel/setup.bash`

### 9.2 一直卡在 `Waiting for /move_base action server...`

原因：

- `nav.launch` 没启动
- `move_base` 节点异常
- ROS master 不一致

### 9.3 `401 Invalid Authentication`

原因：

- `.env` 中密钥无效
- 当前运行环境没有正确加载 `.env`
- Base URL 和密钥不匹配

### 9.4 返回成功，但车没动

通常是底层导航问题，不是适配层问题：

- AMCL 定位不稳定
- 点位落在障碍物内
- 底盘控制链路未接通
